SDD - Design

Now that we have identified the inputs, processes and outputs, we can start to design the program. This is where we will write the algorithm for the program. An algorithm is a step-by-step solution to a problem. We will look at three different ways of writing an algorithm: pseudocode, flowcharts and structure diagrams. Click on the headings below to read about each of these.

Pseudocode

There are several ways to write an algorithm, but the most common way is to use pseudocode. Pseudocode is a way of writing an algorithm in a way that is easy to understand, but not in a specific programming language.

Let's first look at an example, the Calorie Counter program from the Analysis section.

Calorie Counter

Write a Calorie Counter program which...

  • Will ask for the number of calories in porridge, toast, jam and coffee.
  • Calculates the total number of calories in the breakfast.
  • Displays the total number of calories.

We can break this program down into simpler steps by looking at the verbs and nouns.

Calorie Counter Algorithm

  • Ask for the number of calories in porridge.
  • Ask for the number of calories in toast.
  • Ask for the number of calories in jam.
  • Ask for the number of calories in coffee.
  • Calculate the total number of calories.
  • Display the total number of calories.

This is what's known as an algorithm, a step-by-step solution to the problem. Algorithms can often be translated directly into code.

When we start looking at Python programs in this course, you will see the designs of the programes written in pseudocode, and there are some questions at the bottom of this page that will ask you to write pseudocode for a program. You will have to break down the problem described into smaller steps.

Although they won't be used much at the N4 level, let's briefly look at the other two design notation techniques.

Flowcharts

A flowchart is a type of grpahical design notation. It illustrates step-by-step solutions to a problem, providing a visual approach to understanding code. Flowcharts are made up of shapes, each of which represents a different type of action. You can see the most common symbols used for flowcharts below, as well as how a flowchart of the Calorie Counter program could look:

Shape Action
This shape shows the direction of the flow of the program.
This shape shows the start and end of the program.
This shape shows a variable being initialised, or set to a value.
This shape shows a process, or action, that the program will take.
This shape shows a predefined process, or action, that the program will take. You won't need to write the code for this, it will be provided.
This shape shows an input or output.
This shape shows a decision, or a point where the program will take one of two different paths.
This shape shows a connector, or a point where the program will continue on another page.

Structure Diagrams

While flowcharts are a good way to design a program, they can be quite large and complex. Structure diagrams are a simpler way to design a program. They are made up of boxes, each of which represents a different type of action. Below, you can see the most common symbols used for structure diagrams, and this technique used to create an algorithm for the Calorie Counter program:

Box Action
This is a process, or action, that the program will take. In a structure diagram this could include input and output.
This is a predefined process, or action, that the program will take. You won't need to write the code for this, it will be provided.
This box shows a loop, or a point where the program will repeat a set of actions.
This box shows a selection, or a point where the program will take one of two different paths.

The calorie counter program could be designed using the structure diagram shown below.

Look at the example structure diagram for the Calorie Counter program. It starts with the whole program at the top, then breaks the program down into three steps - enter calories, calculate the total and then display the total. Then it further breaks down the 'enter calories' step into four steps - enter the calories for porridge, toast, jam and coffee.

This is a good example of how structure diagrams can be used to break down a program into smaller, more manageable parts.

In a structure diagram, any box that has lines growing out of the bottom of it is a parent. All the boxes below it are its children. The children only happen because the parent box told them to! For example, the Enter Calories box is the parent of the Enter Porridge Calories, Enter Toast Calories, Enter Jam Calories and Enter Coffee Calories boxes.

Writing Pseudocode

Look at the example below:

The Problem: Cinema tickets are £5. A cinema gives a £2 discount on the tickets if a customer spends more than £10 on snacks.

  • Input: The total cost of 4 snacks.
  • Process: Check if the cost is more than £10. If it is, subtract £2 from the ticket cost.
  • Output: Display the final price.

You would have to break this down into further steps, look at this example solution:

  1.   Set ticket cost to 5.
  2.   Set total snack cost to 0.
  3.   Start a loop that repeats 4 times.
  4.       Get snack cost from keyboard.
  5.       Add snack cost to total snack cost.
  6.   If the total snack cost is more than 10:
  7.       Subtract 2 from the ticket cost.
  8.   Set total cost to ticket cost + total snack cost.
  9.   Display total cost.

One tip here is that if you want to add numbers to a total, you have to tell the program what number to start at. That's why we set the total snack cost to 0 in this example. Always set totals to 0 at the start of the program!
