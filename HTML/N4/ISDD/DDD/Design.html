Now that we have identified the end-user and functional requirements of the database, we need to start designing it. This means that we need to ideintify the fields that we need to include in the database, and the data types that we will use for each field.

Data Types

Just like variables used in software development, fields in a database have a data type. The data type of a field determines what kind of data can be stored in it. The table below shows the most common data types used in Access and gives an example of each one.

Data Type Description Example
Short Text Used for storing text data, up to 256 characters. John Smith
Long Text Used for storing text data, up to 65,536 characters. This is a long text field. It can store a lot of text data.
Number Used for storing numbers and numerical data. It can store either whole numbers or numbers with decimal points. 12345
Currency Used for storing currencies. £123.45
Date/Time Used for storing a time, a date, or both. 12/12/2021 12:00:00
Yes/No Used for storing boolean values. Yes

It is also possible to attach files to a field in access using the attachment data type. If you look in the list of data types in the design view, you will also see 'Lookup Wizard' and 'Calculated'. Lookup Wizard is for data validation, and Calculated if you want a field to display a value based on the contents of other fields. We won't be using either of these in the N4 course.

Data Type Questions

Primary Key

Every record in a database must be, in some way, unique. This is so that we don't accidentally create two records with exactly the same date. If that happened, we'd have no way of telling which was which! It's unlikely, but what if two students have exactly the same name and date of birth? They might live at different addresses and have different phone numbers, but what if they lived quite close to one another, their phone number wouldn't even be all that different.

This is why we need primary keys. A primary key is a field in a database that uniquely identifies a record in a database, and it allows us to pick that one record out from the rest if we need to. You can see examples of primary keys in everyday life too! For example:

  • Your National Insurance Number is a primary key for you, it uniquely identifies you.
  • Your student ID number is a primary key for you, it uniquely identifies you as a student.
  • Your passport number is a primary key for you, it uniquely identifies you as a person who has a passport.
  • Cars are uniquely identified by their registration plate number.
  • Customers who sign up for services will have a Customer ID number.
  • You log into services like GLOW using a username that is unique to you.

All of these are primary keys in a database, and when we design a database, our database will also need to have one field that is a primary key. In Access you can see the primary key in the design view because it has the little key icon next to it.

Data Dictionaries

Now that we know which data type we want to use for each field, and which field we want to be the primary key, we can create a data dictionary. A data dictionary is a table that shows the fields in the database, the data type of each field, and the primary key. More advanced data dictionaries will also include how many characters text fields will use, what format certain fields will be in (whole number or decimal number, date format, etc.), whether or not the field is required, and whether or not the field has any type of validation to control what data can be entered into it.

This allows us to plan out our database before we start creating it, and it also allows us to easily see what fields we need to include in the database. For now, we will focus on creating a simple data dictionary that shows the fields, data types and primary key.

Here's an example of a data dictionary for the database that you would need to make for the question below:

Question: A school wants to create a database to store information about its pupils. The database should store the pupil's name, age, and class. The school wants to be able to search for pupils by name, and to display a list of all pupils in a particular class.

Field Name Data Type Primary Key
PupilID Number PK
PupilName Short Text
Age Number
Class Short Text

Note that we only use the fields that were identified in the Analysis stage. You can see which field is the primary key because it says PK (for Primary Key) in that column.
