Now that you know how to design a database, we are now ready to start creating a database in MS Access. So that you can practice even if you are on a computer that doesn't have Access, I have included an embedded database program that you can use on each of these web pages. Using this program is very similar to using Microsoft Access.

Opening Access and Creating a New Database

To open Access, perform the following steps:

  1. Type Access into the search bar in the bottom left hand corner of the screen.
  2. Click on the Microsoft Access Icon.
  3. In the window that opens, click on Blank Database.
  4. Type in the name of your database and click Create.

Datasheet and Design View

In Access, there are two different views that you can use to work with your database. The Design view and the Datasheet view. You can switch between them by clicking on the icon in the top left of the Access window. Below is an explanation of the two views (I have included what the view looks like both in access and in my app below):

View Function Access Icon App Icon
Datasheet View The Datasheet View is used to enter data into the database. It is the view that you will use to add, edit and delete records.
Design View The Design View is used to design the database. It is the view that you will use to add, edit and delete fields.

You will notice that when you create a new database, you will start in the Datasheet View. The first thing you need to do is click on the icon for the Design View.

Once you click on the Design View icon. You will see the window below - Access will ask you to name the table.

After you give the table a name, it will take you to the design view. In Access, the design view looks like the image below and it looks very similar to this in the app.

You can see that there is a list of fields, and a list of data types. The table will start with a field called 'ID' and it will be given the 'AutoNumber' data type. Autonumber means a number that will automatically increase (by 1) whenever a new record is created.

This is where the data dictionary that we created in the design phase comes in, because we can take the field names and data types from our data dictionary and use them in the Design View. For example, look at the data dictionary below:

We can use this to create the fields in the Design View. You can see the completed Design View below, note that for the field with the Primary Key I have just edited the name and data type of the ID field:

Now that we have created the fields, we can switch back to the Datasheet View to start entering data by clicking on the datasheet icon. When we do this, we will be asked to save the table and should click yes.

This will return us to the datasheet view, and you can see that your table now has columns and is ready for you to type in the record data!

Deleting Fields

But what if we have made a mistake and added a field that we don't want? You can delete a field by returning to the design view, and right-clicking on the field. This will open a dropdown menu with a list of options. If you click on Delete Rows then it should delete the field.

Data Properties

There are a number of properties that you can set for each field. You can see the properties for each field by clicking on the field in the design view. The properties for that field will then appear in the bottom half of the screen. You can see the properties for the Customer ID field below:

This allows you to change the properties of the field such as the field size, the default value, whether the field is required, and whether the field is a primary key. The properties displayed are different depending on the data type of the field.

At the N4 level, we are only really interested in the field size, property. The default value depends on whether the field is a text field or a number field.

For text fields, the default value is 255. This means that the user can type in up to 255 characters. If you want to limit the number of characters that the user can type in, you can change the field size to the number of characters that you want to allow. For example, if you change this number to 20, the user can only type in up to 20 characters.

Example Database

I have created the customers database from the data dictionary above in the app so that you can see how it works.

For number fields, the default value is 'long integer'. An integer is a whole number, so you can't type in any numbers with a decimal point like 0.5. If you want to allow the user to type in numbers with a decimal point, you can change the field size to 'double'.
